## 1. Verification and retained boundaries

- `TestBuiltinSourceIsPortableAndExplicitFileIsComplete` checks all eight nodes,
  seven explicit role templates, both plain client presets, embedded discovery,
  absent-config loading without user writes and complete custom override.
- `TestWorkspaceSourceFallbackAndExplicitErrors` and builtin-source negative
  tests cover cwd stability, precedence, explicit empty/missing and existing
  invalid/directory/dangling entries. Valid configuration symlinks still work.
- The recursive fixture's `--builtin --case root` uses the installed binary's
  resource default only for assertions, no CLI --config, no custom configuration
  and no installed personal Skill tree. Actual terminal recipients own POP,
  complete archive digest, exact replies, execution decisions and review
  routing. Its private scope/state files are fixed-actor test bookkeeping, not
  proof of autonomous role-policy compliance, substantive independent review or
  canonical record selection by a model.
- Existing custom recursive cases and old thin entry points remain supported.
  Archived recipient context remains v1 with its existing saved-byte digest;
  generated provenance identifies policy bytes and builtin bundle generation.
- Required runtime dependencies remain Go binary and tmux. Optional record
  helper dependencies are declared in `help records`; perspective prompts are
  read-only Markdown. Domain/provider/personal Nix dependencies stay in
  dotfiles.
- Source MIT copyright 2023 i9wa4 ships in resources/licenses/dotfiles.txt.
  No third-party prose-review body is copied. Detailed procedure ownership is
  in HelpDocs, never duplicated into the thin Skill entries.

The held dotfiles orchestration inputs (#519/#520) contribute finite message
