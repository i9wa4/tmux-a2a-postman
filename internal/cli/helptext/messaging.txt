Messaging — file-first transport

Send literal Markdown via quoted heredoc stdin:
  tmux-a2a-postman send-heredoc --to worker --reply-required <<'POSTMAN_BODY'
  Task request.
  POSTMAN_BODY

Reply after POP and a complete read:
  tmux-a2a-postman send-heredoc --to <sender> --reply-to <message-id> --fills-input-request-id <input-request-id> --no-reply <<'POSTMAN_BODY'
  Task result and evidence.
  POSTMAN_BODY

Cross-session mail uses session:node for a declared direct parent/child
interface. Replies use the original from_session:from. Local mail uses from.
No directory ancestry or same-named role authorizes a cross-session route.

The sender pastes a notification into the existing recipient agent's tmux input
and submits C-m. This transport is shared by all agent types, with no model API
or notifier registration. Notice acceptance, POP, full read and reply are
separate facts. No polling loop or Postman daemon is needed.

Each Markdown archive starts with a one-line JSON HTML-comment envelope,
then a blank line and literal body. POP returns markdown_absolute_path and
pop_receipt_absolute_path; it does not inline the body. After every successful
POP, read the complete archive through EOF before any handling or reply.

Filling an input request closes transport, not task acceptance.
Completion reports include Task artifact:, Original checklist: PASS, Evidence:,
and Remaining blockers: none. Use BLOCKED with Original checklist: FAIL while
requirements remain. Verify evidence and blockers before closing work.
