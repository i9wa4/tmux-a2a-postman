Recipient setup — Bash/Readline notification

In a dedicated interactive Bash tmux pane titled with its configured role:

  export POSTMAN_BIN=/absolute/path/to/tmux-a2a-postman
  export POSTMAN_CONFIG=/absolute/path/to/postman.md
  export POSTMAN_HANDLER=/absolute/path/to/recipient-handler
  source <("$POSTMAN_BIN" notifier-script)

notifier-script prints the setup shipped in this binary. Source it once in
that recipient shell (or from its Bash rcfile). It selects Emacs Readline,
reserves Ctrl-x Ctrl-p, and calls register-notifier directly from Bash.
register-notifier accepts --config or --postman-md and no positional args.
It binds only the calling role and the native pane/PID incarnation.

A notification queues that key sequence, without Enter or message text.
The Readline hook preserves pending input, calls POP once, and passes its
JSON to POSTMAN_HANDLER on stdin. The handler must read the full archived
Markdown through EOF and send any exactly correlated reply. It must never
read the terminal. No polling loop or Postman background process is needed.

The supported recipient host is dedicated Bash with this binding, including
a handler that invokes codex exec. An existing Codex/Claude interactive TUI
cannot use this Bash hook. Missing or stale setup reports unavailable;
accepted means the key was queued, not that POP or reply was observed.
