Recipient setup — existing Codex conversation or optional Bash automation

From each existing Codex conversation, execute as a tool:
  tmux-a2a-postman register-notifier --runtime codex

Options: --runtime codex|bash (default codex), --config or --postman-md
absolute path. No positional arguments. Codex CLI 0.162.1/0.163.0 are tested.

Codex supplies CODEX_THREAD_ID and CODEX_HOME; do not invent IDs or register
from a separate shell. Its executable must be on PATH and CODEX_HOME must be
private. The registered thread cwd must match the native workspace root.
Keep Codex's tui.terminal_title=[] to preserve configured role pane titles.
Register again after /new, switching/resuming conversations or restarting.
Register senders waiting for replies and reviewers as well as workers.

Notifications enter the existing conversation's native input queue. Codex's
own idle watcher currently checks every ten seconds, including --no-daemon.
Busy recipients consume later. The short-lived stdio helper exits after queue
insertion. No thread/turn is started/resumed by Postman and no composer input
is submitted. The recipient must POP the notified ID, fully read the archive,
and send any exact reply. Codex's tool sandbox/approval policy still applies.

For optional dedicated interactive Bash automation:
  export POSTMAN_BIN=/absolute/path/to/tmux-a2a-postman
  export POSTMAN_CONFIG=/absolute/path/to/postman.md
  export POSTMAN_HANDLER=/absolute/path/to/recipient-handler
  postman_setup="$(mktemp)" &&
    "$POSTMAN_BIN" notifier-script > "$postman_setup" &&
    source "$postman_setup"
  rm -f "$postman_setup"
  unset postman_setup

Use bashInteractive on Nix. The setup selects Emacs Readline, reserves Ctrl-x
Ctrl-p and calls register-notifier --runtime bash directly from that shell.
It retains pending input, POPs once and passes JSON to POSTMAN_HANDLER on stdin.
The handler fully reads markdown_absolute_path and sends any exact reply.
Never read terminal stdin. Re-source after shell restart.

accepted proves queue/key acceptance only, not POP or response. Missing/stale
setup is unavailable; ambiguous enqueue is unknown and must not be replayed.
