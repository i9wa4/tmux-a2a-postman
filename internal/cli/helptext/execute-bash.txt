execute-bash — run one exact Bash command with file-mail approval

Usage:
  tmux-a2a-postman execute-bash --command '<bash>'
  tmux-a2a-postman execute-bash --command '<bash>' --config <absolute-postman.md>

Options:
  --command <bash>              Exact Bash source (required)
  --config <absolute-path>      Explicit postman.md override
  --postman-md <absolute-path>  Alias for --config

The caller is the current native tmux pane. The reviewer comes only from
postman.md's command_approver_node. A configured and live reviewer receives
a reply-required mail request whose JSON body has version=1 and the exact
command. The requester waits at most 300 seconds for the exact reply from
that reviewer, matching reply_to and fills_input_request_id. The reviewer
must POP the request before replying. Its reply body is JSON containing
version=1, the exact command, and decision=approved or rejected. Unrelated
inbox messages remain untouched. Rejection, timeout, cancellation, reviewer
loss, or ambiguous topology does not run Bash. Only verified reviewer
absence permits advisory execution.

After the approval request mail commits, execution.notice separately
reports the notification outcome. Native pane-input notification is
disabled because it could submit pending reviewer input, so it reports
unavailable. This does not withdraw the request, approve it, or create a
second request; the reviewer must POP and send the exact decision.

Bash runs outside mailbox locks. Command stdout/stderr stream normally;
Postman status JSON is emitted separately on stderr with execution, self,
and reason. A nonzero Bash exit is status=exited with its exit_status.
Each invocation is independent: an older decision never grants a new run.
The durable pre-dispatch audit is never replayed as command authorization.

This wrapper coordinates review and audit; it does not sandbox Bash.
