# Postman friction triage

Start with the human's words or a faithful citation. Record the affected task,
observed impact, requested effect, constraints, and authority. Separate direct
observations, human reports, inferences, and unknown causes. An agent relay is
not independent proof of its claim.

1. Ask only for missing context that changes ownership or the next action. For
   an anecdote without reproducible evidence, choose one bounded investigation.
2. Check current guidance and relevant open **and closed** issues and PRs,
   including likely owners' bodies. Distinguish an owned episode, duplicate,
   distinct gap, and uncertain owner. Use `git-github-operations` for GitHub
   actions and `postman-records` for a canonical task record.
3. Route before adding work: #1114 owns its 2026-11-27 episode; #1062 owns
   intent/handoff continuity; #1063 owns parallel-result acceptance. #1005
   owns whole named-session evaluation. #891 parents new Postman capabilities.
4. Choose one smallest next action: update an existing owner, draft a narrow
   issue under its parent, gather one missing fact, or record insufficient
   evidence. Link adjacent owners without copying their procedures.
5. Follow the human request or faithful scoped delegation for issue, PR,
   implementation, configuration, or release actions. Advice alone authorizes
   none of them. Do not watch, poll, publish, or change policy automatically.

Return the report and requested effect, evidence limits, owner/duplicate check,
one next action with parent/related links, and any blocker. Give the URL of an
authorized issue change. Do not call an assignment or passing check accepted.
Claim reduced triage burden only with measured comparison to the prior workflow.
